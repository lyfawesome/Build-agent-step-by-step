# 本地部署、模型规模与性能观测

[返回学习手册](README.md) · 来源：[《代码实例学习》](codex://threads/01a06600-a6e2-7302-ab03-3cda43ab87dd)

本章记录另一个对话中的部署知识。模型名单、硬件预算和测试结果属于当时的讨论；本轮没有重新请求 DeepSeek、测试 GPU 或询价，不把历史建议写成当前采购结论。

## 1. 先把部署对象分开

| 对象 | 做什么 | 是否等于模型本身 |
| --- | --- | --- |
| 模型权重与 tokenizer | 保存训练得到的参数，把文本与 token 相互转换 | 是模型交付的重要组成部分，但不是完整服务 |
| 推理引擎 | 加载模型、执行推理、管理显存和请求调度 | 否 |
| 模型 API 服务 | 暴露客户端可以请求的接口、鉴权、配额等 | 否 |
| LangChain | 组织模型、消息、工具和其他组件的调用 | 否 |
| LangGraph | 执行有状态流程、节点和流转逻辑 | 否 |
| Coding harness / Agent 应用 | 组织读文件、编辑、终端、权限、循环和上下文管理 | 否 |
| 观测系统 | 记录延迟、错误、调用链和评估结果 | 否 |

调用云模型时，应用不需要自己加载权重，也通常不需要维护 GPU 推理服务；但仍要处理超时、限流、密钥、工具权限、数据出境和结果校验。换成本地模型时，应用层逻辑可以部分复用，不代表 API 行为完全相同。

## 2. vLLM、SGLang、Ollama 是什么

三者都与运行模型有关，不是三个模型，也不是 LangGraph 节点的替代品。

| 名称 | 在学习中可以怎样理解 | 真正选型前需要验证 |
| --- | --- | --- |
| vLLM | 面向模型推理与服务的引擎，常用于服务化和多请求调度 | 目标模型、硬件、量化格式、工具调用解析和并发配置 |
| SGLang | 用于模型推理与服务的系统，也涉及结构化生成和调度 | 同上，不能只比较宣传吞吐 |
| Ollama | 简化本机模型下载、运行和接口调用的工具 | 模型格式、上下文、硬件利用、服务控制与应用兼容性 |

这不是性能排名。一个服务暴露 OpenAI 风格接口，只代表部分协议兼容；还应逐项验证 `tools`、`tool_choice`、流式工具参数、JSON 输出、usage 和错误响应。参考各自官方入口：[vLLM](https://docs.vllm.ai/)、[SGLang](https://docs.sglang.ai/)、[Ollama](https://docs.ollama.com/)。

## 3. “框架能离线”不等于“整个应用离线”

LangChain / LangGraph 可以在本地运行；是否联网取决于应用接入的模型、工具、存储、追踪和依赖。

面向保密单位时，应逐项检查：

1. 模型权重、tokenizer、嵌入模型和依赖包能否提前导入内网；运行时是否仍自动下载。
2. LLM、检索、数据库、文件、工具执行和审批服务的实际地址。
3. 追踪、遥测、错误上报、更新检查和许可证校验是否有外联。
4. 日志是否包含客户原文、图纸内容、参数、代码或凭据。
5. 身份认证、文件访问、网络出口、备份恢复、审计和升级流程。

本机运行 Python，再调用公网 DeepSeek API，仍然会把请求中的数据发送到外部服务。私有部署要求应覆盖整个数据流，不能仅以“使用开源框架”判定合规。

## 4. 模型规模术语

| 术语 | 意义 | 容易误解的地方 |
| --- | --- | --- |
| B / T | 十亿 / 万亿；27B 是 270 亿参数 | 不是文件大小，也不是上下文长度 |
| Dense | 稠密模型，与稀疏专家激活方式相区分 | 参数量相近不代表能力和速度相同 |
| MoE | 混合专家；每个 token 的计算会选择部分专家 | 不等于只存储被激活的参数 |
| 总参数 / 激活参数 | 整体规模 / 一次 token 计算涉及的部分规模 | A3B 不能直接按整个模型只有 3B 估算存储 |
| FP32 / BF16 / FP16 | 数值表示格式 | BF16 与 FP16 都是 16 位，但数值范围等性质不同 |
| FP8 / INT8 / INT4 | 更低位宽的浮点或整数表示等 | 不同量化方案、硬件和内核不能只按位数比较 |
| 量化 | 用较低精度等方式表达参数或缓存，减少资源需求 | 工具选择、参数生成、长文本能力仍需回归测试 |
| 上下文窗口 | 一次请求可处理的 token 容量边界 | 不是长期记忆，也不保证所有长文信息都能有效利用 |
| KV cache | 保存注意力计算中可复用的 key/value 等中间数据 | 不是保存“模型全部思考过程”的数据库 |

只按 27B 参数和位宽做理想化估算，权重本体约为：16 位 54 GB、8 位 27 GB、4 位 13.5 GB。这里采用十进制 GB，未计量化元数据、混合精度部分、KV cache、运行工作区及其他开销，不能据此直接承诺某张显卡能跑多长上下文。

容量规划至少同时看权重、上下文、活跃请求数量、缓存精度和运行时开销；不能统一加一个固定百分比就覆盖所有情形。多卡显存也不是无需条件即可合并使用，还依赖模型并行支持、切分方案和互联。

## 5. 并发、吞吐和延迟不是同一个指标

| 指标 | 在问什么 |
| --- | --- |
| 用户数 | 有多少人在使用系统 |
| Agent 任务数 | 有多少工作流在运行或等待 |
| 活跃模型请求数 | 此刻多少请求在占用推理资源 |
| 工具并发数 | 同时有多少数据库查询、求解或文件操作 |
| TTFT | 请求后多久得到第一个 token，测量时需说明是否包含排队与网络 |
| TPOT | 输出阶段平均每个 token 所需时间，需说明统计口径 |
| TPS | 每秒 token 数，必须注明单请求还是服务总量、输入还是输出 |
| p50 / p95 延迟 | 一半 / 95% 请求的延迟落在什么范围以内 |
| 错误率 / 排队时间 | 系统是否过载、失败或长时间等待 |

十个 Agent 不一定同时产生十个模型请求：其中一些可能在等工具或人工。反过来，一个 Agent 也可能并行调用多个模型。应设置全局队列和并发预算，再用真实任务压测；历史讨论中的“先试 2—4 并发”只是实验起点，不是容量保证。

## 6. LangSmith 与其他观测方案

LangSmith 用于应用追踪、调试、评估等，不是模型服务，也不是使用 LangChain / LangGraph 的必需条件。它支持自托管，但官方将该能力列为 Enterprise 附加项；完全隔离部署还要核实许可和网络条件，不能等同于免费离线版。[官方自托管说明](https://docs.langchain.com/langsmith/self-hosted)

另一个对话讨论过以下候选；这里只保留类别和评估方向，不宣布其当前许可证或商业功能免费：

| 候选 | 主要评估方向 |
| --- | --- |
| Langfuse | LLM 调用链、提示词、成本与评估工作流 |
| MLflow tracing | 把生成式应用追踪与实验、评估管理结合 |
| OpenLIT | 面向生成式应用的观测与 OpenTelemetry 集成 |
| OpenTelemetry + Jaeger / Tempo + Grafana | 自行组合通用追踪、指标与展示能力 |
| Phoenix | LLM 追踪、分析与评估；单独核对使用版本的许可 |

选择时检查：本地存储、离线运行、字段脱敏、权限、保留周期、导出能力、版本许可证和维护成本。无需一开始全部安装；先把一次模型调用和一次工具执行关联到同一 `run_id`，记录耗时、状态和受控输入摘要即可。

日志与 Evidence 不完全相同：日志说明发生过什么，Evidence 还需要来源、适用范围、版本和业务审查。工具运行成功的日志不能替代工程计算审查。

## 7. 历史模型、硬件与报价讨论如何保留

指定对话曾讨论 Qwen、GLM、DeepSeek、Kimi、MiniMax、Step、MiMo 等国产模型，以及 Qwen Code、DeepSeek Harness、OpenCode、Aider、OpenHands 等编码应用候选。它们的具体型号、开放权重状态、许可证、工具调用能力和兼容性均需按版本重新核实；“国产”“开放权重”“开源”“允许商用”“能完全离线”是不同条件。

此前生成的 [Qwen3.8-27B 本地部署与成本说明 HTML](../../artifacts/Qwen3.8-27B_本地部署与成本说明.html) 保留了当时的配置与预算讨论。文件标题不构成本轮对型号规格的独立验证；历史预算不是当前报价，不应直接用于采购。

稳定的筛选顺序是：数据和许可边界 → 真实业务任务效果 → 工具协议与结构化输出 → 硬件容量和延迟 → 运维和总成本。专业设计 Agent 与个人编码 Agent 可以共用模型服务，但应分开权限、任务预算和数据边界。

当前教学入口是 [demo_config.py](../demo_config.py)。读取环境配置后创建客户端，并不表示已经验证账号、额度、连通性或模型能力。

指定对话曾报告普通对话、流式、JSON、工具选择、参数解析及 LangChain 适配测试通过；这是历史实测记录。本轮只整理文档，未重新运行这些付费或联网请求。

该对话还指出另一套应用适配器可能存在超时/重试配置不一致，以及“提示词要求 JSON”不等于 API JSON 模式的问题。这些应在对应代码版本上复查，不能直接认定为本目录 demo 的现存缺陷。

密钥保留在本机环境或未跟踪的环境文件中，仓库提供无密钥模板与配置说明。没有提交本机环境文件，不妨碍正确配置后的程序运行；反之，有 `.gitignore` 也不能证明历史记录从未泄露过凭据。
